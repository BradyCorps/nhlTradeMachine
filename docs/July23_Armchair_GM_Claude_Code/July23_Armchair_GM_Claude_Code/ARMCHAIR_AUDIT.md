## 1. State and season lifecycle

- [x] **ST1 New run:** clear all prior sim state; restart at the 2026–27 offseason/2026 draft. Current bug: the old sim continues while only the draft resets. — root cause was that `originalDb` served two incompatible jobs: "league at the start of the CURRENT season" (overwritten by every Cup Run rollover) and "the league to reset to". After a run advanced, no pristine 2026-27 league existed anywhere, so a second run began on a league already aged up to three years — players retired, rookies drafted — while the run state said Year 1. Added an immutable entry baseline (`entryBaselineRef`, captured once at load via `cloneLeague`, never rewritten); starting *or* abandoning a run restores it, which also closes the deferred CX5 abandon-baseline item. The two reset lists (season rollover vs new run) were merged into one shared `resetSeasonState`, so a field added to one can't be forgotten by the other; it now also clears `matchResults` and a stale `cupDraftSummary` (a previous run's draft popup could reappear). Fixed a regression from the earlier CX5 patch: `onStart` called `resetTrades()`, which sets `showTeamSelect(true)` and popped the franchise picker over a team the user had just chosen. Regression in `__tests__/league-baseline.test.ts` (baseline survives rollover mutation); five canaries pin the wiring.
- [x] **ST2 Draft picks:** traded picks stay unavailable; completed draft years leave every asset selector. A traded 2027 first cannot reappear in that draft, and Year 2 cannot offer 2027 picks. ![ST2](assets/13-stale-2027-draft-picks.png) — an off-by-one in the prune boundary. Rolling into Cup Year N *holds* the draft for `SEASON.draftYear + N - 1` (Year 2 → 2027), but the rollover kept picks with `year >= currentDraftYear`, preserving exactly the picks it had just converted into rookies. The rule was also written twice with two different comparisons — the rollover's `>=` and Draft Night's `year === SEASON.draftYear` (a no-op, since the pick inventory starts at `firstTradablePickYear` 2027). Both now route through `dropSpentDraftPicks` / `draftYearForCupYear` (`app/lib/draft-picks.ts`), where the boundary is inclusive of the draft just held. Pruning at the source means every selector agrees at once, since they all read `db.players`. Pick ownership already carried correctly through the rollover (`players: [...nextPlayers, ...picks]`), so removing the spent year is what stops a conveyed first reappearing. 8 unit tests in `__tests__/draft-picks.test.ts` (including the traded-pick case and repeated rollovers); 3 canaries. ![ST2](assets/13-stale-2027-draft-picks.png)
- [x] **ST3 Positions:** alternative positions persist into Lineups. ![ST3](assets/01-lineups-position-persistence.png) — the eligibility engine already existed (AG3: `isC`/`isW`/`isF` in `app/lib/lineup-order.ts` check both primary and secondary, shared by `LineupEditor` and the default ordering, forward-flex only so no id lands in two group orders). What was broken was the lookup feeding it: `SECONDARY_POSITIONS[p.name]` was a raw exact-string index while everything else in `roster-assembly.ts` matches through `canonicalNameSlug`, so every mapped player whose feed name carries diacritics silently got `null` — including Teuvo Teräväinen and Tomáš Hertl, and Teräväinen is the very example `lineup-order.ts` cites as the reason the feature exists. Added `secondaryPositionFor()` with a slug-keyed index (accent-, case- and punctuation-insensitive). Also added the missing persistence coverage: `secondaryPosition` survives `advanceSeason` (verified through three consecutive rollovers) and a saved wing slot survives a roster change via `hydrateLineupOrdersForRoster`. 9 unit tests in `__tests__/secondary-position-persistence.test.ts` (one asserts every curated row resolves, so a future accented entry can't rot); 2 canaries.
